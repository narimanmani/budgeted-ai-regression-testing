# Eight-task held-out-workload execution

These files are separate v8 adaptations of the preserved v7 execution library.
They keep the original CG1 policy byte-identical and preserve the comparison
criteria, K=2/4 budgets, five arms, cold/warm histories, two repetitions and80
trajectories. They do not start native applications or models on import.

`runner.py` imports the cohort/prompt/input-scoped `MeteredApplication` from
`development_v8/acquisition.py`. Root supplies the actual authorized campaign,
native runtime, validation contracts, public changes, authenticated impact
builder, whole-design affordability gate and source guard. There is no default
native campaign or implicit authorization.

Each application/repetition has 20 trajectories. Physical ceilings are 48 common
old-profile questions, 160 own warm-history questions and 360 selected comparison
questions, totaling 568. Four blocks total 2272. Every warm trajectory acquires its
own eight paired observations. Profiles use three paid observations per task;
the A_BAD profile is released only after all20 episode1 trajectories close.

The runner pays `runtime.prepare_states` as common metadata work before old
profiles, warm calibration and each logical episode. HEALTHY/A_BAD is ready for
episodes1and2; HEALTHY/B_BAD is ready for episode3. At most two native APIs may be
resident. These preparations precede individual policy episode timers. Required
setup wall/cost remains charged in each standalone operational view; shared
physical work is counted once. The runtime must reject unprepared query states
and never lazily start an API inside a policy pair.

The exported `Contracts` class uses the already verified canonical native source
projection, including grouped OpenWebUI source arrays. Its primary judgment still
uses the unchanged v3 factual checkers. The source guard covers this reused source
projection and the scoped acquisition implementation.

`evaluate.py` preserves the saved-output policy-recheck and matched retention/
utility semantics, adapting the required own warm-history frame from12 to8
pairs. `resource_feasibility.py` binds the exact four-block order,568-unit slots
and2272-unit whole main design. It debits actual cumulative GPU work from one
sealed main baseline and applies paid OLD latency projections. Its24000-second
admission ceiling uses a600-second native lifetime reserve; nonpreemptible calls
are measured afterward, with any overshoot/unknown work retained and stopping
continuation. Physical preemption is not guaranteed.

Root must complete passed fresh qualification and separate reference banks for
both applications, freeze all production code/inputs and full remaining budget,
and pass native source/context/model/accounting audits before using this runner.
Development outcomes do not become warm history or policy features. The source
guard still verifies the original v7 guidance freeze plus the new v8 execution/
controller/checker and root-supplied validation freeze files.

The tests use synthetic in-process clocks, native transports and source fixtures.
Their results establish software behavior, not CG1 effectiveness or native
application readiness.
